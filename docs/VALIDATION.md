# Experimental protocol and acceptance gates

1. Record source URL, retrieval date, SHA-256, license, engine commit, network ID, config, rule system and random seed. Preserve raw files locally; no redistribution without permission. Normalize name aliases, dedupe by canonical move sequence plus board size/setup/komi where appropriate. Audit malformed games, variations, era and incomplete metadata. Only mainline for MVP; distinguish passes from absent nodes; handicap and setup stones must be handled or explicitly excluded.
2. Split by complete game before extracting positions or augmenting rotations/reflections. Remove cross-source duplicates before splitting; chronological holdout is preferred, with opponent/era stratification where feasible. Exclude test games from all player-specific tuning. Human SL may have seen historical public SGFs during pretraining; report possible contamination; use recent or independent positions and comparative baselines, not absolute memorization claims.
3. Compare uniform, Human SL rank, matched-era pro baseline, simple position bias and learned residual. Report held-out move negative log likelihood, top-1/top-5, calibration, phase-wise performance, player identification vs matched opponents and confidence intervals clustered by game. Check if apparent style merely identifies era, color, opponent, joseki or tournament conditions. Validate after down-ranking with blinded style-choice tests and feature distribution distances. Do not claim professional identity replication.
4. Rank: run paired-color games against baseline bots with fixed conditions, several seeds and independent positions; estimate rating/interval from outcomes. Compare calibrated style variants at equal strength, not only win rate. Suggested initial gate: >=100 paired games per selected profile and rank band, then expand if intervals too wide. Human amateur anchors are required before interpreting numerical labels as OGS ranks. Rank settings are not guaranteed equivalent to server rankings.
5. Stability: 19x19 first; separate 9x9/13x13 validation. Include ko, superko, suicide under configured rules, handicap, pass, end scoring, import/export, captures, board orientation, illegal moves and power-loss recovery. Fail safe if no legal policy. No silent strong-engine fallback.
6. Desktop/Android: measure median and p95 move latency, peak RAM, model disk size, battery and thermal throttling on actual target hardware. Initial target p95 <=3s on selected desktop, <=5s mobile for low-visit play, subject to device measurements. Offline cold start and 30-minute play session in airplane mode. Verify same exported profile loads on both. Hardware simulation covers placement, removal, wrong coordinates, reconnect, duplicate events, unplug, rollback.
7. Release only with test report, known limitations and notices. No claims of measured strength, authentic style or phone compatibility until measured.
